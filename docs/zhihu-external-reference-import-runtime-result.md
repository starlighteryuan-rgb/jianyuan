# Zhihu ExternalReference Import Runtime Validation

## Result

Five candidates from the validated local Zhihu dataset adapter output were
successfully imported through the existing boundary:

```text
ZhihuExternalDatasetAdapter
  -> RetrievedExternalReference
  -> ExternalReferenceService.import()
  -> IngestionService.ingest()
  -> isolated in-memory repositories
```

No production database or user-data repository was used. This was not a full
dataset import: the adapter produced its validated candidate set for sample
selection, but exactly five candidates entered `ExternalReferenceService`.

## Identity and Provenance Validation

For every imported sample:

- `ExternalReferenceService.import()` returned success.
- `IngestionService` created one Record with one distinct Evidence Unit ID.
- The stored `sourceFingerprint` exactly matched a fresh call to the existing
  `computeSourceFingerprint(..., sha256)` logic using imported origin, platform
  actor, canonical URL, unmodified excerpt, and capture-time semantics.
- The Evidence Unit ID was generated by the existing root-source ingestion path
  and had the existing `eu_<uuid>` form.
- The stored role set was exactly `[external_reference]`.
- The source excerpt was preserved verbatim.
- The stored time semantic was `capture_time` at
  `2026-09-12T16:00:00.000Z`.
- Provenance was preserved as `origin: imported`, `actor: platform`, canonical
  URL in `sourceRef`, and the manifest capture time in `capturedAt`.
- No lineage parent was created because each external reference is a root source.

`ExternalReferenceService` and real `IngestionService` against a fresh,
process-local repository graph. It did not call Prisma, connect to the
production database, bypass ingestion, modify Domain semantics, or replace the
existing source fingerprint or evidence identity implementation.
