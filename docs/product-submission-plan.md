# 产品说明计划书

## 一、项目概述

**产品名称：** 见渊（Personal Awareness）

**一句话定位：** 从用户自己的原话出发，帮助其重新看见过去经历与当下问题之间可能存在的联系，并把最终解释权留给用户。

**核心问题：** 人们并不缺少信息、经历和思考，真正困难的是：过去获得的经验往往散落在不同时间与情境中，到了需要判断和行动的时刻，无法及时回到注意力中。普通笔记工具擅长保存内容，却很少帮助用户辨认记录之间可能存在的结构；直接给出人格标签或结论的系统，又容易用有限信息替用户定义自己。

见渊（Personal Awareness）希望在二者之间建立一条更克制的路径：保存原话、呈现线索、引入外部视角，并邀请用户自行回应。产品不追求“替用户得出答案”，而是帮助用户更有依据地继续观察和思考。

## 二、核心创作思路

“见”代表看见、觉察与重新回望；“渊”代表经验中可能存在、却尚未被注意到的更深层次。见渊不是要替用户探明一个确定答案，而是让原本沉在注意力之外的经历与思考重新变得可见。英文技术概念 Personal Awareness 保留，用于表达产品所围绕的个人觉察能力。

### 1. 为什么需要个人觉察

一个人的选择通常不是由单条知识决定，而是由经历、行为、思考和时间变化共同影响。许多重要线索只有在多次记录被放到一起时才可能显现。见渊（Personal Awareness）的价值，是让这些过去的内容在合适的时刻重新参与当下思考，而不是让它们停留在信息仓库里。

### 2. 为什么从“自己的话”开始

用户的原始表达是体验的起点。系统先保留用户愿意留下的原话，不把输入立即改写成人格判断，也不通过连续追问把 Capture 变成聊天。这样可以尽量减少外部语言对用户自我理解的预设，让后续线索仍然能够回到可追溯的个人表达。

### 3. 为什么系统不直接定义用户

相似行为可能来自不同情境，少量记录也不足以形成稳定结论。因此，本项目把“事实记录”“可能关系”“待检验解释”和“用户赋予的意义”分开处理。系统可以指出某个模式也许值得重看，但不会宣称“你就是这样的人”，也不提供心理诊断。

### 4. 如何保留用户主动权

系统提出的是可能性，用户可以认同、不确定、认为暂时不适用，或先放一放。用户的回应不会反向修改事实，也不会把一个假设升级为事实。工程层同时区分存储、分析、被动展示和主动展示权限，使用户可以控制内容如何被使用。产品遵循的基本原则是：系统守住事实边界，用户决定个人意义。

## 三、产品体验流程

```text
用户表达
   ↓
Capture
   ↓
Awareness
   ↓
External Reference
   ↓
Reflection
```

### 1. 用户表达

用户从一句真实、具体、愿意在未来重新看见的话开始。内容可以是事实、感受，也可以是一句尚未想清楚的判断。

### 2. Capture（捕捉）

Capture 的职责是接住原话并保留来源与时间语义。它不自动分析输入，也不要求用户与系统持续对话。正式工程路径会把用户表达作为可追溯记录进入既有的摄取边界；当前竞赛 Demo 为避免引入账号和数据库，仅在浏览器会话内演示这一动作。

### 3. Awareness（觉察）

系统把多条记录之间可能存在的关系呈现为“值得回看的线索”。这一阶段强调观察而非断言：线索可能成立，也可能只在特定情境下成立。系统保留不确定性，并允许用户回到原始记录重新判断。

### 4. External Reference（外部参考）

当用户需要更多视角时，系统可以提供来自外部世界的经验、实践建议或专业观点。外部内容用于拓宽提问方式和理解背景，不作为证明用户特征的材料，也不会成为用户身份的一部分。

### 5. Reflection（反思）

用户对线索作出自己的回应。可以选择有共鸣、不确定、暂时不适用或先放一放，也可以补充自己的表达。回应记录的是用户此刻的位置，不意味着系统已经获得关于用户的最终结论。

## 四、技术实现方案

### 1. 总体架构

项目采用 TypeScript、Next.js 与 React 构建，整体为模块化单体架构。系统按职责划分为四层：

- **展示层：** 承担 Capture、Awareness、References、Reflection 等用户界面与演示路径。
- **应用层：** 组织记录摄取、关系判断、假设、发现、反思和外部参考等用例。
- **领域层：** 保存产品最重要的事实边界、证据规则、状态规则和用户意义归属原则。
- **基础设施层：** 提供内存仓储、Prisma 仓储、加密身份生成以及知乎外部数据适配器。

这种分层使界面、外部平台和存储方式可以变化，而核心判断边界保持稳定。

### 2. 核心处理路径

个人觉察主路径由记录、关系、假设、发现与反思组成。关系和假设不会直接被当作事实；系统通过确定性的权限、来源、去重、证据独立性和状态规则限制其进入下一阶段。语义判断与规则执行被分开：语义判断可以由可替换的接口提供，是否合法、是否重复、是否越过证据边界则由代码负责。

当前仓库默认使用可重复验证的确定性判断实现，因此无需 AI 密钥也可以完成工程测试。真实 AI 能力尚未接入竞赛 Demo。

### 3. 展示层实现

当前 Demo 使用完整的引导式网页体验，保留 Awareness 示例、Discovery 示例、知乎 External Reference 示例及刘看山展示角色。首页直接说明产品用途，并允许用户从自己的话开始。演示输入和回应只保留在当前页面或浏览器会话中，不上传、不调用 AI，也不创建账户。

### 4. External Reference 架构

外部参考是与个人证据链并行的“侧边层”。内容进入系统时会保留平台来源、规范化链接、原始文本和获取时间，并被固定标记为 `external_reference`。现有规则会阻止这类内容进入个人关系和假设的证据判断，避免外部观点被误写成个人事实。

### 5. 知乎外部数据接入

仓库已实现两种知乎适配路径：面向知乎开放平台搜索接口的在线适配器，以及面向本地知乎搜索数据集的只读适配器。适配器负责把结果映射为统一的外部参考对象，不负责定义用户，也不会自行触发个人分析。

已有运行验证完成了本地数据集的读取、校验、去重与冲突隔离，并使用抽样内容走通 External Reference 导入边界。竞赛展示页面使用经过整理的静态示例，不在浏览器中携带知乎访问密钥，也不进行现场网络调用。

### 6. 数据隔离原则

- 用户原话、系统解释和外部内容拥有不同的来源与角色标记。
- 外部作者、热度、排名、评论和编辑时间不会被转换为关于用户的事实。
- 外部参考不能证明个人假设、定义用户或建立个人行为基线。
- 相同来源不会因为摘要、重述或重复导入而被计算成多份独立证据。
- 用户对外部内容的回应属于用户自己的意义表达，但外部内容本身仍不是关于用户的证明。

仓库已提供内存与 Prisma 两类仓储实现；当前竞赛 Demo 不连接生产数据库，也不包含用户账户。

## 五、知乎生态契合度

### 1. 知乎适合作为“外部视角层”

个人觉察常常需要的不只是概念解释，还包括“别人如何经历类似问题”。知乎社区同时包含个人经验、实践方法、观点讨论与专业知识，能够为用户面对的具体问题提供多种可比较的理解角度。这与本项目“先看他人如何经历，再看知识如何解释”的外部参考定位相契合。

### 2. 从个人问题回到社区知识

产品不是把知乎内容直接推荐给所有用户，而是从用户正在回看的问题出发，在用户需要外部视角时引入相关内容。知乎提供更广阔的经验与知识背景，见渊（Personal Awareness）则负责保持这些内容与个人经历之间的边界。两者结合后，用户获得的不是一个替代答案，而是更多可以继续追问和比较的视角。

### 3. 不以社区权威替代个人经验

回答者身份、赞同数量、排序和平台权威不能证明某个观点适用于当前用户。项目在适配阶段不会把这些字段映射为个人含义，也不会根据热度自动推断用户特征。即使用户认同某条知乎内容，这种认同也只是一条新的个人回应，不会使原外部内容成为个人事实。

### 4. 尊重内容和平台边界

知乎接入使用明确的外部数据适配层。系统保留内容标题、正文摘录和可追溯链接，清理的仅是搜索高亮标签与传输用追踪参数；异常响应、无效链接和冲突内容会被拒绝或隔离。访问密钥由运行环境提供，不写入领域数据或公开前端代码。外部结果不会被自动导入，需经过明确选择和既有存储权限检查。

## 六、应用场景与价值

### 1. 个人反思

当用户面对反复出现的困扰、重要选择或阶段变化时，可以先记录自己的语言，再回看不同时间的表达是否存在可讨论的共同结构。产品提供线索，但不替用户作价值判断。

### 2. 知识探索

用户可以从一个与自身有关的问题出发，引入知乎中的经验、方法和专业观点，对比不同解释，形成更具体的问题，而不是停留在泛化的信息搜索中。

### 3. 长期自我理解

在未来具备账户与长期存储后，分散在不同时间的记录可以形成可追溯的变化轨迹。系统关注“哪些理解发生了变化”，而不是固化一个永久的人格标签。该能力属于后续发展方向，当前 Demo 仅展示其产品逻辑。

### 4. 学习与成长

在学习计划、项目复盘、职业发展和创作过程中，用户可以记录真实经验、观察行动模式、参考社区知识，并由自己决定下一步尝试什么。产品强调证据、反例与不确定性，有助于形成更审慎的自我复盘习惯。

### 5. 社会价值

本项目尝试提供一种更负责任的人机协作方式：技术不以标签代替理解，不以外部权威压过个人经验，也不把一次回应解释成永久身份。它鼓励用户在事实、观点和个人意义之间保持区分，并将社区知识转化为可继续思考的公共资源。

## 七、当前 Demo 展示说明

当前 Demo 已提供一条可完整点击的引导体验：用户从首页输入自己的话，进入 Capture，随后查看 Awareness 演示快照、知乎 External Reference 示例，并在 Reflection 页面作出自己的回应。刘看山作为展示向导，通过预设状态帮助用户理解当前阶段；这些状态不调用 Agent、模型或工具，也不根据用户内容进行推断。

Demo 中的记录数量、可能观察和待检验解释均为竞赛展示用固定快照，目的是让评委在有限时间内理解产品结构，不代表对实际体验者进行分析。页面始终把外部参考与个人反思分开，并使用“可能”“值得回看”“待检验”等表述，避免把系统输出包装成结论。

## 八、未来发展方向

以下内容均为后续可能方向，不是当前 Demo 已有功能：

1. **受约束的 AI 辅助：** 在现有语义判断接口后接入模型，用于提出关系候选、可能解释和反例；所有结果仍需通过确定性证据与权限规则，不能直接生成用户结论。
2. **个人账户与隐私控制：** 增加认证、账户隔离、数据导出与删除机制，使用户能够明确管理自己的长期数据。
3. **长期使用与变化回看：** 在用户授权下持续积累记录，呈现观点、情境和自我理解随时间发生的变化，而不是建立固定人格档案。
4. **实时知乎视角入口：** 将现有知乎适配器接入用户主动触发的检索界面，在保留来源、权限和外部参考隔离原则的前提下，提供更及时的社区知识视角。
5. **更细致的反思偏好：** 让用户控制提醒频率、是否追问、何时暂停以及哪些主题可以再次出现，减少不必要的干预。

见渊（Personal Awareness）的未来扩展不会改变其核心立场：系统可以邀请用户看见可能性，但不能替用户走向结论。
